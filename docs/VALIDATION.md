# 验证记录

版本：0.1.5。目标系统：Windows x64。

## 可重复执行的检查

在仓库根目录安装依赖后运行：

```powershell
npm ci
npm run build
npm test
npm run test:rust
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
```

- 前端类型检查及 Vite 生产构建。
- Node.js 测试 17 项：提示词操作、类别、导入导出、模板和旧数据迁移。
- 原有 Rust 测试 22 项：原生数据操作、文件备份、迁移、输入框选择和 Windows 输入结构；新增 4 项剪贴板单元测试及 1 项需显式启用的剪贴板集成测试。
- 发布版通过 `custom-protocol` 嵌入前端资源。

## 0.1.5 多行变量回归检查

通过 98 项浏览器断言，覆盖 1120 / 800 像素管理窗口和 400 / 320 像素悬浮面板：

- 变量窗口支持多行内容；Enter 插入换行而不提交。
- 保留空行、缩进、制表符、末尾空格和换行；Windows CRLF 在文本框中规范化为 LF。
- 同时填写多个变量，重复变量展开后内容一致，保留 `$&` 等字面内容。
- 模拟原生命令边界，检查复制、填入、发送的最终 action 和正文；未在真实聊天中触发发送。
- 检查真实浏览器预览复制路径（使用内存剪贴板替身），输出正文与预期逐字一致。
- 窄窗口无对话框横向溢出，页面无运行时错误。

## 0.1.4 剪贴板回归检查

新增 4 项 Windows 单元测试：独立 Unicode 备份、HTML/RTF/自定义格式、位图和文件列表内存、GDI 位图复制。测试验证原句柄释放后副本仍可读取。

Windows 集成检查默认跳过，避免常规单元测试改动桌面剪贴板。显式运行：

```powershell
cargo test --manifest-path src-tauri/Cargo.toml --lib clipboard::tests::native_clipboard_transaction -- --ignored --test-threads=1
```

该检查临时使用测试数据，并保留独立备份以在结束时恢复原剪贴板；不输出用户内容。已检查文本重复填入、ANSI 自动转换、空剪贴板、多格式富文本、图片、文件列表、错误路径、短暂占用及操作期间另行复制。

## 0.1.3 已检查的界面场景

通过 39 项浏览器界面检查，覆盖 1120 / 800 像素管理窗口及 400 / 320 像素悬浮布局：

- 每张卡片直接显示复制、仅填入和发送三个按钮，更多菜单只保留编辑、副本和删除。
- 窄布局无卡片横向溢出。
- 复制获得准确正文；填入和发送正确进入各自操作路径（浏览器预览返回原生操作提示）。
- 默认操作改为复制后，发送按钮仍进入发送路径，复制按钮仍执行复制。

## 0.1.2 已检查的界面场景

标准 Vite 页面与离线预览分别通过 22 项交互检查，包括：

- 首次启动只有“默认”类别和一条 `test`。
- 创建空类别、刷新保留、重复名称校验、编辑器中创建类别。
- 删除空类别及非空类别，提示词移至“默认”并保留正文。
- 管理窗口与悬浮编辑器同步类别变更。
- 导出、合并及替换导入保留空类别；无效导入不覆盖现有数据。
- 提示词编辑、搜索、收藏、模板复制、主题设置和删除。
- 升级旧浏览器数据时清理内置示例并保留原始副本。
- 悬浮布局没有横向溢出，页面没有运行时错误。

## 手动验收

1. 启动桌面版，创建类别和提示词，退出后重开并确认保存。
2. 删除一个包含提示词的类别，确认条目移到“默认”。
3. 导出 JSON，再测试合并和替换导入。
4. 选择临时文本编辑窗口，先检查“仅填入”的内容、焦点和换行。
5. 在目标聊天中检查 Enter / Ctrl+Enter 的实际发送行为。

自动发送未在真实 Codex 会话中完成验收；不能将逻辑测试通过视为目标应用兼容性验证。
